# Agent Note: 手机宽度下的 Web 控件保持可达

Status: implemented

[English](2026-08-15-phone-width-web-controls-remain-reachable.md) | 中文

## 问题

Web 外壳把每个窄框架都当作缩小的桌面界面。自动收起仍在网格中保留 56px 侧边栏轨道，打开时则恢复 280px 网格栏；因此在 390px 手机上，会话在关闭侧边栏时只能获得 334px，打开时更只剩 110px。编辑器工具栏、审批操作、问题页脚和计划审阅决定也仍是单行组合。可选标签与控件可能占用超过卡片的宽度，导致最后的 Send、Submit 或审批操作在纵向视图外被裁切。

## 决策

AppFrame 在低于 560px 时使用手机布局。导航不占用任何网格轨道：关闭状态是在 44×52px 浮动表面中的现有切换控件，打开时则按解析后的侧边栏宽度，让同一个已挂载侧边栏覆盖会话栏。两种状态下，会话都保留完整框架宽度，侧边栏缩放手柄保持隐藏；在更宽的界面中，普通 56px 轨道和网格内缩放行为均保持不变。侧边栏根据 owner 提供的实际渲染宽度派生紧凑呈现，因此会跟随 AppFrame 测得的框架，而不会单独根据浏览器窗口作出决定。

在同一 viewport 宽度下，会话把编辑器留白改为 8px，并让标题栏避开浮动切换控件。InputBar 把卡片设为尺寸容器；不宽于 460px 时，左侧控件保留在工具栏第一行，模型、上下文与主操作则占据完整第二行。权限触发器保留现有的仅图标模式；模型触发器省略次要的推理强度说明，完整选择仍可在菜单中查看。

审批按钮可以换行并平分操作行。通用问题把翻页器与反馈保留在页脚第一行，并让「跳过」与「提交」占据完整第二行。计划审阅操作横跨页脚并可换行。卡片保留现有限高与内部滚动区，因此新增操作行只会占用页脚高度，不会把决定操作移出 viewport。

## 考虑过的替代方案

**在所有宽度下缩小 56px 轨道。** 否决：改变桌面轨道只能收回少量手机宽度，而打开网格内 280px 侧边栏后，390px 会话仍会缩到 110px。

**完全隐藏导航，并新增汉堡按钮、遮罩、焦点陷阱和自动关闭行为。** 此次修正不采用：现有侧边栏切换控件已经提供无障碍的打开与关闭路径。复用这个已挂载控件既不需要第二套导航状态机，也能把网格宽度还给会话。

**截断更多标签，并让所有编辑器控件留在一行。** 否决：权限、模型、推理强度、上下文、计划和扩展控件会随组合而变化。隐藏固定子集无法保证最后的操作始终可达，而第二行可以从结构上保证这一点。

## 后果

纵向模式用户可以保留完整会话宽度，并且无需旋转设备即可使用 Send、审批、问题与计划审阅操作。打开导航后，它会覆盖会话左侧，直到用户将其关闭；这项聚焦修正刻意不加入独立遮罩或自动关闭策略。密集编辑器状态会增加一行工具栏，决定卡片也可能增加一行页脚，以部分纵向空间换取可达控件。

真实 Web 回放场景会测量 390×844 viewport。审批快照记录 44×52px 的关闭切换控件、390px 会话、366px 编辑器、位于第二行的主操作，以及不存在横向页面溢出。问题快照记录每个按钮都位于 334px 卡片内，决定操作处于第二行；计划审阅场景则验证三个操作都保持横向包含。单元覆盖会固定零宽度手机侧边栏轨道、其 44px owner 宽度、覆盖层展开，以及缩放手柄保持隐藏。
